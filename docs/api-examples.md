# API documentation and examples

These examples use the default local server:

```text
Base URL: http://localhost:8080
Content type: application/json (except CSV uploads, which use multipart/form-data)
```

The same workflow is available in the Postman collection at
`postman/six_index_api.postman_collection.json`.

## 1. Check that the API is running

```bash
curl -i http://localhost:8080/api/health
```

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{"status":"UP","service":"index-review"}
```

## 2. Upload the CSV snapshots

For a complete review, import the SPI universe, security market data, and
current composition. The combined endpoint requires all three multipart field
names shown below.

```bash
curl -i -X POST http://localhost:8080/api/import/all \
  -H "Accept: application/json" \
  -F "spiUniverse=@data/spi_universe.csv" \
  -F "securityData=@data/sec_data.csv" \
  -F "composition=@data/composition.csv"
```

The sample files produce a `201 Created` response similar to:

```json
{
  "spiUniverse": {
    "dataset": "SPI_UNIVERSE",
    "inputRows": 409,
    "storedRows": 409,
    "deduplicatedRows": 0
  },
  "securityData": {
    "dataset": "SECURITY_DATA",
    "inputRows": 409,
    "storedRows": 409,
    "deduplicatedRows": 0
  },
  "composition": {
    "dataset": "COMPOSITION",
    "inputRows": 20,
    "storedRows": 20,
    "deduplicatedRows": 0
  }
}
```

The files may also be uploaded independently. Each request uses the multipart
field `file` and returns one `ImportResponse` with the same four properties:

```bash
curl -i -X POST http://localhost:8080/api/import/spi-universe \
  -F "file=@data/spi_universe.csv"

curl -i -X POST http://localhost:8080/api/import/security-data \
  -F "file=@data/sec_data.csv"

curl -i -X POST http://localhost:8080/api/import/composition \
  -F "file=@data/composition.csv"
```

CSV imports are header-driven and BOM-tolerant. SPI universe and security data
use `;` separators; composition accepts `,` or `;`. Empty, malformed, or
conflicting input returns `400`; identical duplicate rows are deduplicated.

## 3. Trigger the SMI Q3-2026 review

The review request has no body. The index code and review period are path
variables.

```bash
curl -i -X POST \
  http://localhost:8080/api/index-reviews/SMI/Q3-2026/run \
  -H "Accept: application/json"
```

The sample scenario returns `200 OK` and a persisted report. The numeric
`reviewResultId` is generated by the running database, so clients should save
the value from this response rather than assume it is `1`. The following is a
representative response excerpt; the real response contains complete arrays.

```json
{
  "reviewResultId": 1,
  "indexCode": "SMI",
  "reviewPeriod": "Q3-2026",
  "cutOffDate": "2026-09-10",
  "reviewDate": "2026-09-21",
  "status": "COMPLETED_WITH_WARNINGS",
  "createdAt": "2026-09-21T10:00:00Z",
  "totalEligibleSecurities": 408,
  "totalSelectedConstituents": 20,
  "currentMembers": [101, 102],
  "constituents": [
    {
      "securityId": 177,
      "rank": 7,
      "ffmcap": 84534783495.25,
      "rawWeight": 0.0612345678901234,
      "finalWeight": 0.0612345679,
      "cappingFactor": 1.0,
      "decisionType": "JOINER",
      "decisionReason": "Security ranked inside top 20 by FFMCAP.",
      "capped": false
    }
  ],
  "decisions": [],
  "joiners": [177],
  "leavers": [103],
  "unchanged": [],
  "notSelected": [],
  "rejectedSecurities": [],
  "auditEvents": []
}
```

The arrays in the example are shortened for readability; the actual report
contains all 20 selected constituents and the complete ordered audit trail.
The integration scenario includes security `177` as a joiner and `103` as a
leaver. A warning status is expected when security-level input warnings cause
affected securities to be rejected. Fields such as `currentMembers` and the
decision/audit arrays depend on the imported snapshot and should be treated as
data, not fixed constants.

## 4. Retrieve the report JSON

Use the ID returned by the run request to retrieve the complete persisted
report:

```bash
curl -i http://localhost:8080/api/index-reviews/results/1 \
  -H "Accept: application/json"
```

Alternatively, retrieve the latest report for the index and review period:

```bash
curl -i http://localhost:8080/api/index-reviews/SMI/Q3-2026/latest \
  -H "Accept: application/json"
```

Both endpoints return the same `ReviewResponse` JSON shape. A missing report
returns `404 NOT_FOUND`.

To retrieve the ordered audit events for one security in the report:

```bash
curl -i \
  http://localhost:8080/api/index-reviews/results/1/securities/177/audit \
  -H "Accept: application/json"
```

Each audit item contains `timestamp`, `ruleCode`, `securityId`, `message`,
`inputValue`, and `outputValue`. The endpoint returns an empty array when the
report exists but the requested security has no audit events.

## API status and version aliases

Successful imports return `201 Created`; review execution and retrieval return
`200 OK`. Invalid requests/imports return `400`, review validation failures
return `422`, missing resources return `404`, and unexpected execution or
persistence failures return `500` using the project's `ErrorResponse` shape.

The import and review routes also accept the equivalent `/api/v1/...` prefix,
for example `/api/v1/index-reviews/SMI/Q3-2026/run`.
